## 实现内容

1. **输入无关的小表。** 预计算 16 种库存可用掩码对应的唯一类型、四种候选顺序，以及透射/反射规则和 8 个字节位掩码。赋值耗尽某类型时清位，撤销恢复时置位；节点直接查询表，不再反复创建候选列表、元组。常量表约 8 KB，独立实验的一次构建中位约 33.6 微秒。
2. **按尺寸复用几何。** 缓存键是 `(width, height)`，表项只保存前格、后格、透射后继、反射后继。目标命中位在每次求解内重新附加，所以改变目标或激光也能安全共享几何。表项按需计算，并非每题先遍历整块棋盘。
3. **按静态域复用前驱。** 键包含尺寸与每个格子的初始光学域，覆盖固定块、初始可用库存类型及外部空格。库存数量变化但类型域相同时可以复用；某种库存归零、空格容量归零或固定块改变时使用对应的不同键。反向 BFS 的距离、队列、已访问状态仍归本次求解所有。
4. **缓存命中时直接读取。** 热循环直接读取已经填好的几何/前驱表项，未命中时才调用构建函数。保持原遍历顺序、目标早停、重启预算和剪枝频率。

跨题缓存从不保存求解答案、动态赋值、剩余库存或失败结论。第三阶段只释放本次求解的前驱表引用，不清空其他求解可能复用的共享表。LRU 元数据使用锁保护；表项是按相同键确定的不可变元组，并发重复填充结果相同。

## 冷启动与空间代价

完整 5,997 题按尺寸连续排列，并在同一工作进程内运行，因而包含跨不同题目的缓存复用。为区分这种收益，另外选取 38 个代表案例，各版本每题重复 3 次并轮换测量顺序：

| 场景，114 次求解累计 | 时间 | 相对基线降低 |
| --- | ---: | ---: |
| 基线 | 3.772 秒 | — |
| 候选，每题前清空缓存 | 3.518 秒 | 6.74% |
| 候选，预热静态表后求解 | 2.628 秒 | 30.32% |

这些测量全部正确，具体布局与 9 项计数均一致。冷启动包含实际建表成本；暖测试的预热不计入测量时间，明确只衡量表已经存在时的求解成本。常量表在模块导入时只构建一次，其成本已单独测量。

两层 LRU **各最多保留 65,536 个状态槽**。超出容量的单张表只供当前调用使用，不常驻缓存；最近未用的表自动淘汰。38 题序列结束后，缓存键、表容器、整数及元组的去重递归大小为 **10,933,738 字节，约 10.43 MiB**。这是该序列实测值，不是固定 RSS 或所有输入的峰值。

另在 `n44_a10_c10_open` 上独立用 `tracemalloc` 测量冷启动：基线峰值 2,812,180 字节，候选峰值 3,329,660 字节，增加约 0.49 MiB。内存测量与计时分开进行。缓存容量以状态槽计量；正在求解的引用可在淘汰后继续存在，进程总内存还包含输入、搜索栈、Python 运行时等。

Python 接口：

```python
from lazor.search import clear_search_caches, search_cache_info, solve_search

clear_search_caches()  # 释放跨题保留表，也可用于冷启动测量
result = solve_search(puzzle, timeout=1)
print(search_cache_info())  # capacity / hits / misses / evictions / state_slots
```

没有采用的方案也保留了试验结果：全棋盘立即建表增加冷启动耗时；共享反向距离的前缀回放增加管理成本；缓存每个状态的大整数位掩码，在 44×44 全填时约占 16.47 MiB，而筛选收益不足 1%。
