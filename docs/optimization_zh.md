# 计算量优化与验证

本文记录第一轮优化及其测量快照。后续论文检索、第二轮实现和扩大后的对照实验见 [研究与第二轮优化](research_optimization_zh.md)。

本轮优化作用于 `lazor` 主程序。默认求解和编辑器继续使用经过优化的 SMT；命令行与 Python API 增加精确剪枝搜索。旧的 `dfs_baseline.py` 保留作为完整枚举对照。

## 改动

- **模拟器**：直接读取网格，避免每个光线状态反复调用 `Block.interact` 做相同参数校验；透射已经证明前方可通行，不再做一次相同的碰撞查询。保留完整分光、回环、合流、光路顺序和重复状态统计。
- **SMT**：先用库存限定每格可能的类型，再计算从光源出发的潜在可达图；只为保留的光线状态创建符号变量。复用格子条件和转移条件，用原生精确计数约束表达库存，批量提交约束，验证阶段复用条件求值。建模和验证会分批检查时间预算。
- **剪枝搜索**：只决定已到达光路依赖的格子，显式栈替代递归；缓存整数状态几何，用位集记录访问状态，库存不足时直接排除选项，唯一选项直接赋值。乐观可达性检查允许未定格子选择所有剩余类型，如果这种放宽情况下仍碰不到目标，便可安全剪枝。全部目标已通过确定路径命中后，将剩余库存填入未决定的格子，最后完整模拟复核。
- **测试工具**：固定随机种子生成尺寸/库存的全部交叉组合；每次计时使用独立进程、逐项保存原始结果，并支持条件一致时断点续跑。

搜索的乐观检查忽略部分格子之间的相关性，因此它只能用于证明某个分支不可能成功；只有完整布局经过真实模拟后才返回成功。`candidates_tested` 是最终完整模拟的布局数，通常只有 0 或 1；比较搜索工作量应同时查看 `states_expanded`、`ray_states_processed`、`branches_pruned`。

两种算法都会在验证输入后提前拒绝偶奇性不可能的目标，SMT 仍保留可导出的 UNSAT 证明模型。搜索先尝试空格优先的分支顺序；超过 4,096 个节点仍未完成时，仅重试一次分光块优先的顺序，共用原时间预算。节点、光线状态和重试次数累计报告；只有某次完整搜索耗尽全部分支才证明无解。这种顺序启发式改善了本次样本，但不保证每道题都更快。

## 使用

```powershell
python -m lazor boards/custom_test.bff --solve --algorithm search --timeout 10
python -m lazor boards/custom_test.bff --solve --algorithm smt --timeout 10
```

`search` 不需要 Z3，`--model` 仅适用于 SMT。两种算法都保留精确库存、固定方块、禁止放置格、多光源和分光规则；超时均返回 `timeout`，不作无解结论。

## 可复现验证

修改前主程序保存于 `tmp/optimization_baseline/lazor`。计时脚本为 `tmp/measure_optimization.py` 与 `tmp/run_optimization_measurements.py`，原始数据在 `outputs/optimization/before.json` 和 `outputs/optimization/after.json`，包含代码及输入 SHA-256。

现有 5 个棋盘的 SMT 与剪枝搜索每项运行 3 个独立进程，取算法耗时中位数；不包含进程启动与导出。SMT 时间包含 Z3 加载、建模、求解与验证。模拟器采用 7 批重复追踪取中位数。修改前与修改后分阶段运行，微秒级差异受机器负载影响，应以原始批次判断。

实测结果（秒，中位数）：

| 棋盘 | 修改前 SMT | 优化后 SMT | 新增剪枝搜索 | SMT 加速 |
| --- | ---: | ---: | ---: | ---: |
| custom_test | 0.734713 | 0.239419 | 0.006144 | 3.07 倍 |
| mad_1 | 0.142743 | 0.059283 | 0.000351 | 2.41 倍 |
| loop_demo | 0.084900 | 0.041072 | 0.000108 | 2.07 倍 |
| placement_demo | 0.096378 | 0.045083 | 0.000184 | 2.14 倍 |
| refraction_demo | 0.092688 | 0.041907 | 0.000128 | 2.21 倍 |

单独的 44×44 固定 C 分光压力场景包含 7,404 个光线状态、7,402 条线段；模拟由 15.836 毫秒降到 12.698 毫秒，耗时下降 19.8%。该场景用于测模拟器，不属于 4—10 可移动库存的求解矩阵。

15 个代表用例、每项 2 秒预算的最终结果：

| 算法 | 已求解且复核 | 已证明无解 | 超时 | 错误结论 |
| --- | ---: | ---: | ---: | ---: |
| 优化后 SMT | 4 | 5 | 6 | 0 |
| 剪枝搜索 | 9 | 5 | 1 | 0 |

剪枝搜索剩余超时用例为 `n24_a10_c10_obstacles`。这次未将延长预算后的结果混入 2 秒限时表。详细结果见 `outputs/optimization/summary.json` 和 `outputs/scaling_smoke_final.json`；较早的 `outputs/scaling_smoke.json` 属于中间版本。本项目只在列出的输入上实测，不将单个棋盘的加速比推广为全部规模的保证。

正确性检查中 **167 项单元测试全部通过**，包括小棋盘全布局对照、旧模拟器逐段顺序对照和重试回滚/共享超时；另独立生成 1,500 个 1×1 至 3×3 混合随机棋盘，对照旧版穷举与旧模拟器，共覆盖 32,620 个完整布局，结论全部一致。44×44 测试覆盖 1,936 次强制赋值及超过 1,900 层分支，验证显式栈不会触发 Python 递归限制。

全量尺寸/库存矩阵已经生成 5,997 个用例；生成时对每个有解用例的证据布局做了模拟验证。求解计时先运行 15 个代表用例，覆盖 4×4、24×24、44×44。完整矩阵的生成不等于全部求解性能已经测量。具体覆盖、运行预算与限制见 [测试集说明](scaling_tests_zh.md)。
