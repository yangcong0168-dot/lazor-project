# Lazor 状态转移规划与光线模拟代码讲解

程序现在把摆法写成布尔和整数约束，用 Z3 求出一个可行配置，再用已有模拟器
复核光路。原有读取、手动摆放、编辑器和输出功能仍然可用。

## 数据怎样流动

```text
.bff 文件 → Puzzle
    ↓ solve_constraints
方块决策变量 + 状态转移 + 可达性/来源约束 + 目标约束
    ↓ Z3 返回满足约束的模型
读取方块位置 → build_layout → simulate 独立复核
    ↓
PlanningResult + SimulationResult → 报告 / SVG / BFF 快照
```

自动求解过程不再按层枚举摆法。光线模拟中的队列只用于检查一个已经确定的棋盘，
它与寻找方块位置是两个不同任务。数学公式和正确性证明见
[状态转移规划模型](planning_model_zh.md)。

## 1. 两种坐标必须分清

放方块用 `(列, 行)`，从 0 开始。例如 `(1, 1)` 是第二列、第二行。
访问棋盘时却是 `grid[行][列]`，因为列表先存行，再存行中的格子。

激光与目标使用半格坐标，一个方块宽、高各为 2 个单位。第二列、第二行的格子
占据 `x=2..4, y=2..4`，中心是 `(3, 3)`，左边面中点是 `(2, 3)`。
原点在左上角，x 向右增大，y 向下增大。

```python
placements = {(1, 1): "C"}  # 把 C 放在第二列、第二行
# 光从 (2, 3) 以 (1, 1) 方向前进，正在进入这个 C 的左侧面。
```

方向 `(1, 1)` 表示右下，`(1, -1)` 表示右上。每一步把方向分别加到 x 和 y。

模拟器要求光源位于格子面的中点，即 x、y 一个奇数，一个偶数，这样才能唯一判断
撞到水平面还是竖直面。角点和格子中心的光源会收到明确错误。
目标仍可使用解析器允许的整数坐标；没有光经过的目标会留在未命中集合中。

## 2. layout.py：先检查摆法

`build_layout(puzzle, placements)` 把手动摆放加到原始关卡上。它检查：

- 坐标是不是合法的整数 `(列, 行)`，并且在棋盘内。
- 类型是不是 A、B 或 C。
- 原格子是不是 `o`，不能放在 `x` 或替换固定块。
- 对应类型的可移动库存是否充足。

函数复制棋盘和库存，反复模拟不同摆法不会改变原始关卡。允许只放一部分方块来
调试，但会保留 `remaining_blocks`，避免将未完成的摆法当作完整解。
固定块与移动块光学行为相同，`fixed` 不改变反射或遮挡规则。

## 3. models.py：Block 负责一次相互作用

`Block.interact(direction, face)` 接收入射方向和撞到的面，返回所有出射方向。

| 方块 | 返回方向 | 含义 |
| --- | --- | --- |
| A | 一个反射方向 | 光被反射 |
| B | 空元组 | 光在这里终止 |
| C | 原方向、反射方向 | 光分成透射和反射两条分支 |

撞竖直面只改变 x 方向，撞水平面只改变 y 方向：

```python
from lazor.models import Block

Block("A").interact((1, -1), "vertical")
# ((-1, -1),)：右上变成左上

Block("C").interact((1, -1), "horizontal")
# ((1, -1), (1, 1))：继续右上，以及反射到右下
```

Block 不负责找碰撞位置或移动光线。把方块行为单独封装，可以独立测试反射规则。

## 4. simulation.py：从面中点走到下一面中点

状态 `(x, y, vx, vy)` 表示光在当前点，朝给定方向准备进入前方格子。
`_cell_ahead()` 找到前方格子，并判断进入的面：

- x 为偶数：在竖直面上，用 x 方向决定进入左格还是右格。
- x 为奇数：此时 y 为偶数，在水平面上，用 y 方向决定进入上格还是下格。

前方没有方块就直行；有方块就调用 `Block.interact()`。
每个出射方向都生成下一点 `(x + vx, y + vy)`。

记录线段前还检查它实际穿过的格子，不能穿进 A 或 B 的内部。
这个检查处理光源恰好夹在两个方块之间的情况：朝 A 发射后，反射分支如果撞到
紧贴后方的 B，会被挡住；若后方也是 A，两面之间的零距离反弹不会新增光路。

这样也解决了 C 块出口重复分裂的问题：光从 `(2, 3)` 进入第二列、第二行的 C，
沿 `(1, 1)` 透射，一步到达 `(3, 4)`。下次处理时检查下方的新格子，
不会再次处理刚离开的 C。如果下方也是 C，它是另一个方块，仍会正常分裂。

一步沿对角线从一个面中点到另一个面中点。棋盘边界上的终点保留，越界后的
线段不加入结果。

## 5. 为什么使用队列和 seen

一个 C 会产生两条分支，多条激光也要一起处理，因此用 `deque` 保存待处理状态。
每次取出一个状态，将其后续状态放回队列，直到队列为空。

```text
取出一个状态
    ↓
是否处理过完全相同的位置和方向？
    ├─ 是：跳过
    └─ 否：记录位置、计算光学行为、把后续状态入队
```

`seen` 保存完整的 `(x, y, vx, vy)`。只记录位置会出错：同一点往左上走和往右下走，
未来路线不同。位置和方向都相同，则未来路径完全相同，不必重做。

这让反射闭环自然终止，不需要一个可能误截断正确光路的最大步数。
有限棋盘只有有限面中点，每个点只有四种对角方向，因此不同状态总数有限。

`repeated_states` 不等于“循环数量”。两条光路汇合、两个相同光源，也可能产生
重复状态；它只记录跳过了多少次重复工作。

## 6. 命中目标与完整解

每个新状态先把当前位置加入 `visited_points`，再处理碰撞。
因此光源起点、棋盘边界，以及 B 遮挡面的接触点都能命中目标。

所有光路取并集后：

```python
hit_targets = puzzle.targets & visited_points
missed_targets = puzzle.targets - visited_points
```

`all_targets_hit` 只看是否有遗漏目标。
`is_solution` 还要求所有可移动库存都已合法放完。
两者分开能区分“已经覆盖目标”和“满足完整解条件”。

命中全部目标后仍继续处理剩余状态，让输出图展示完整光路。
模拟未通过只说明当前摆法失败，不能说明关卡无解。

## 7. solver.py：把未知摆法写成约束

每个允许放块的格子有一个整数变量，值为 0、1、2、3，分别代表空、A、B、C。
固定块和禁止放置的格子保持原值。库存等式要求 A/B/C 的数量分别恰好等于输入库存。

光线状态仍为 `(x, y, vx, vy)`。求解器为几何上可能的直行和反射建立条件边：
是否启用某条边，取决于边前方的方块决策变量。C 会同时启用透射和反射边。

每个状态有两个辅助变量：

- `r_s`：该状态是否能从某条实际光源到达。
- `d_s`：一个到达见证的层级，用来证明它的来源。

光源状态设为可达、层级为 0。一个非光源状态要声称可达，必须至少有一个
层级更小、已经可达、且转移条件成立的前驱。所有可达状态的有效出边也必须
继续到达后继，因此模型保留折射的全部分支。

只给可达性写循环等式可能产生错误：一圈与任何光源都不相连的反射环，可以
互相声称“我是从前一个点来的”。严格下降的见证层级排除了这个情况。
有光源接入的真实闭环仍然允许，因为层级只约束选中的来源见证，不要求每条
实际光路边都让层级增大。

最后，每个目标要求它所在位置至少有一个方向状态可达。Z3 同时满足这些约束，
返回所有格子的类型。这里是可行性规划，没有优化最少方块或最短光路；Z3 内部
仍会进行逻辑推理和搜索，不是一个闭式公式。

## 8. 返回结果与复核

`solve_constraints()` 返回 `PlanningResult`：

| 状态 | 含义 |
| --- | --- |
| `solved` | 约束模型有解，而且返回摆法通过独立光线模拟 |
| `no_solution` | 约束被证明不可满足，即该模型下无解 |
| `timeout` | 时间预算用完，不能据此判为无解 |
| `unknown` | 求解器未能给出确定答案，可查看 `reason` |

统计字段包括建模、约束求解、复核、总耗时，以及状态数、条件转移数、变量数、
约束数和 Z3 版本。这些是模型规模，不能解读为测试过多少个候选摆法。
`reachable_states` 是模型声明可达的完整状态集合。

成功后会重新调用 `simulate()` 检查库存、固定块、目标与光路。
输出函数仍使用 `search=` 参数，但传入的是同一个成功的 `PlanningResult`，
这样不会把别的关卡统计贴到当前图上。

## 9. 运行、导出数学模型

```powershell
python -m pip install -r requirements.txt
python -m lazor boards/mad_1.bff --solve --model outputs/mad_1.smt2 --output outputs/mad_1_planning.txt --svg outputs/mad_1_planning.svg --save-board outputs/mad_1_planning.bff
python -m unittest discover -s tests -v
python -m lazor.benchmark boards --output outputs/planning_benchmark.json --timeout 110
```

当前电脑的 `py -3` 是旧版本，可使用 README 中的 `$projectPython` 路径。
本项目也支持把依赖安装到 `.deps`；普通读取、模拟和编辑不需要 Z3。
SMT-LIB `.smt2` 文件记录实际提交给求解器的变量与约束，方便审阅模型。
`--model` 必须和 `--solve` 一起使用；`--force` 允许替换已有输出。

手动模拟的命令不变：

```powershell
python -m lazor boards/placement_demo.bff --place C:1,1 --simulate
python -m lazor boards/loop_demo.bff --simulate
```

规划结果图显示规划总耗时与模型规模，并区分最后一次光线模拟耗时。
原生图片格式是 SVG，无须第三方绘图库；PNG 预览可从 SVG 转换。
BFF 结果是摆法快照，其中已放方块变成固定块；保存的原始关卡仍可重新求解。

## 10. 验证范围

测试包括文件读取、方块行为、光路循环、折射、多光源、输出往返和图形编辑器。
规划测试还要检查无源循环不能凭空命中目标、真实有源循环可行、返回解能重放，
以及超时/unknown 不误报无解。

基准测试的总耗时包含读取、建模、求解和独立复核，不包含进程启动和图片导出。
当前仅 `mad_1.bff` 来自作业 PDF 示例，其他板是教学/回归夹具。官方完整测试集
和隐藏关卡尚未提供，不能把本地结果当作全部评分关卡都达标。
旧 `outputs/` 文件可能来自此前的求解器版本；当前结果请重新生成。
GitHub 提交、最终 tag 和 release 发布仍是单独事项。
