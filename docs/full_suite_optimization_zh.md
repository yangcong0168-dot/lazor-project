## 测试范围与计时口径

- 完整矩阵：正方形边长 4～44，每种尺寸独立组合 A=4～10、C=4～10；跳过 10 个容量不足的 4×4 参数组合。每组生成开放、障碍/多光源、奇偶性无解三类，总计 5,997 题。
- 有解题 3,998 个，无解控制 1,999 个。无解控制具有不可能命中的偶数奇偶性目标，不代表困难无解问题。求解器不读取预埋解答。
- 全量对比使用 `search`，每题内部预算 1 秒。父进程另设 1 秒宽限后终止异常阻塞的工作进程；内部超时和外部终止分别记录，均不会记为无解。
- 同一 Python 3.12 环境、同一输入哈希、串行执行，不同时运行其他性能实验。每个版本在隔离的持久工作进程中执行，模块导入已预热；逐题重新建立搜索状态。算法耗时不含导入、解析、父进程验证和日志写入，进程往返时间另存。
- 所有返回布局均由公共模拟器独立复核目标和完整库存。JSONL 逐条写入，可校验代码、输入、运行参数后续跑。与上一轮每题重新启动进程的结果，不直接混合统计。
- PAR-2 将未及时正确完成的题按两倍预算计分，越小越好；它不是实际平均运行时间。完成题分位数排除了超时，必须结合超时数量阅读。

## 基线发现

旧版本完整完成 5,997 次试验：3,898 个有效解、1,999 个正确无解、100 个超时，没有错误答案或进程错误。累计算法耗时 281.395 秒，PAR-2 为 0.063596 秒。

100 个超时包括开放题 70 个、障碍题 30 个，尺寸从 7×7 到 44×44。例如 `n07_a09_c06_open` 在一秒内展开 224,486 个节点，说明无效分支造成的长尾并不只在大棋盘出现。全套累计展开 7,892,189 个节点，处理 224,322,765 个光线状态。

另一个热点是强制赋值后的重复撤销：`n17_a09_c04_open` 使用 59,390 个节点和 163,122 次强制赋值；`n39_a10_c06_obstacles` 使用 9,437 个节点和 74,056 次强制赋值。它们提示了后续压缩强制传播工作的空间。

第一次全量优化版本将超时从 100 降到 7，没有新增超时，累计算法耗时降到 156.601 秒。将这 7 题的预算提高到 5 秒，仅 `n27_a09_c04_obstacles` 在 1.736 秒完成，其余仍超时。SMT 同为 5 秒时解出 3 题：`n24_a07_c06_open` 用时 2.488 秒、`n27_a09_c04_obstacles` 4.709 秒、`n35_a04_c05_obstacles` 4.755 秒；其他 4 题仍超时。所有返回答案均复验通过。这些输入有独立的预埋有解证据，超时不是无解。

随后选全部 7 个残余、旧版最慢完成 20 题、中间版最慢完成 20 题、跨尺寸控制题和原始棋盘，去重后共 66 题。试验逐步得到：

## 实现与正确性边界

状态压缩利用 `stride=2W+1` 为奇数，所有合法面中点都满足 `x+y` 为奇数，因此线性点号 `y*stride+x` 恒为奇数。只存其右移一位的编号，解码时恢复低位 1；这是双射，不合并不同方向或位置。大棋盘的光线位集合长度约减半。

反向目标引导在固定格和初始库存允许的乐观图上，按需执行反向 BFS。它考虑方向、前方格的反射条件和后方格的透光条件；从同一目标已算出的距离可跨回溯复用。批量查询待处理光线，找到最近的候选就停止扩展，避免一个不可达候选强迫每次扫完整张图。

这些距离只用于选择先处理哪条光线、先尝试哪个格值，**不用于删除搜索分支**。未知距离也不代表不可达。新阶段受节点和光学工作量双重预算限制，随后有完整搜索兜底；所有阶段共享原始截止时间，预处理也计入预算。合法解仍须通过独立完整模拟。

最终阶段顺序为空格优先、远目标/C 优先的反向指导、近目标/A 优先的反向指导、完整几何排序搜索。前三阶段各最多约 4,096 个决策节点或 65,536 个光线工作量，阈值在外层循环检查；最后阶段没有重启阈值。两个反向阶段按真实方向状态的反向距离排序，分别保留分光与节省分光块的倾向。第二种引导开始时重置目标与距离队列，复用静态前驱图；最后阶段释放已不使用的逆图缓存。

`ray_states_processed` 包含反向 BFS 弹出状态的工作，不能把新增预处理藏在计数之外。逆向表最坏占 O(目标数×状态数) 空间，状态编号压缩不等于整个求解器的峰值内存一定减半。每 256 个光线工作检查截止时间，这不是硬实时保证；外层工作进程有独立看门狗。

## 原生实现对照

另在 `tmp/native_search/` 实现了旧冻结搜索算法的 C++ 原型，仅用于测量实现开销。500 个随机案例的结果、完整布局及 7 项工作计数与旧 Python 版本逐项一致；另外验证了 44×44、1,936 次赋值、88 个目标及零预算。每个原生返回解仍由 Python 完整复验。

在旧版 100 个 1 秒超时题上，原生版本以同样 1 秒核心预算解出 31 题，仍有 69 题超时。在旧版最慢完成的 20 题上，原生全部完成且布局/工作量相同：旧 Python 核心中位数 0.56054 秒、原生核心 0.01693 秒、原生端到端 0.03563 秒。逐题核心耗时比的中位数为 39.44。

这是挑选慢题的实现开销对照，不能外推为完整矩阵的 39 倍提速。Python 采用预热持久进程，原生逐题启动可执行文件；原生核心时间不含 wrapper 预验证、进程启动和外部复验，端到端另记。原型移植的是旧搜索，不与最终 Python 的成功率合并。后续可以移植经过验证的新搜索策略，但其效果尚未测量。

## 进一步可行的方向

最终版额外对 3 个代表案例做了 cProfile，输出在 `outputs/full_optimization/profiling/`。分析器有自身开销，下面的累计占比不能当成整套基准的比例，各函数累计值也不能相加。它们用于确定下一轮顺序，尚未据此修改生产代码。

| 样本 | 热点证据 |
| --- | --- |
| n44_a10_c10_open | 仅 264 个搜索节点，9 次乐观可达检查；`optimistic` 累计占约 92.8%，包含几何查询 |
| n13_a07_c05_obstacles | 反向距离查询 138,492 次，累计约 36.9%；`assign`＋`undo` 合计仅约 5.1% |
| n44_a09_c06_obstacles | `optimistic` 累计约 65.8%，反向距离查询约 26.8% |

据此，建议从低风险改动开始，而不是先换整个求解器：

1. **先跳过没有选择意义的排序。** 待处理光线只有一条时，不必计算一组距离再选择唯一项；库存仅剩一种合法类型时，不必先做候选优先级排序。保留目标更新时机、截止时间和后续回溯语义。这比首先微调 `assign/undo` 有更直接的热点证据。
2. **减少乐观可达检查中的重复工作。** 最终全量执行了 99,921 次检查、处理约 1.09 亿光线状态。先分别记录检查成本和成功剪枝次数，减少重复入队/几何字典查询，试验紧凑索引数组；再按收益调整检查频率。频率变化只跳过剪枝检查、保留完整搜索时可以保持正确性，但也可能令搜索树变大，必须实测。不能仅凭 cProfile 将未单独计时的整数位运算认定为瓶颈。
3. **强制传播和等效域压缩。** 全套仍有 6,506,951 次强制赋值。所有未定格的有效域只剩同一类型时，可尝试隐式读取，减少逐格写入/撤销。反射后方格当前只区分透光集合 `{o,C}` 与阻挡集合 `{A,B}`，也可探索延迟确定具体类型；后者必须维护库存容量并在最终精确分配，改造成本更高。
4. **图割冲突学习与回跳。** 对已经证明目标不可达的分支，提取阻断所有路径的已赋格值，跨重启保存；库存耗尽和反射后方格也必须纳入冲突原因。预算耗尽的前缀不能当成失败约束，缓存还须区分已决定为空和未决定的格。依据：[SAT Modulo Monotonic Theories](https://ojs.aaai.org/index.php/AAAI/article/view/9755)、[Nogood Recording from Restarts](https://ijcai.org/proceedings/2007/19)、[Prosser 的冲突导向回跳](https://doi.org/10.1111/j.1467-8640.1993.tb00310.x)。
5. **增量维护可达图。** 用依赖索引仅更新被改变格影响的转移，并在回溯恢复；但库存类型归零会影响全部未定格。不能简单按入度计数，否则脱离光源的环可能错误地自我支持；需要来源可达性证书。依据：[Fully Dynamic Single-Source Reachability in Practice](https://arxiv.org/abs/1905.01216)。
6. **抽象状态缓存/模式数据库。** 对小区域的真正抽象问题预计算可证明的下界或失败表。多个目标可能共用方块，同一镜面也可能被多条光线利用，不能把各目标最短路或反射次数直接相加当作所需方块数。依据：[Culberson 与 Schaeffer 的 Pattern Databases](https://webdocs.cs.ualberta.ca/~jonathan/publications/ai_publications/compi.pdf)。

原生内核适合在这些规则稳定后移植，前文已有实现开销的实证。下一轮每次只改变一组因素：先跑小盘穷举、回环/分光/阻挡、库存回滚与截止时间测试，再跑完整矩阵、重复诊断和另行生成的新种子集。当前 164 例已被查看，今后再拿它调参就不能继续称为未见留出集。

这些研究方向和具体项目实现之间的对应是工程推导，论文中的其他问题规模和加速数字不能直接套用到本项目。

## 复现

```powershell
python -m lazor.full_benchmark --manifest outputs/scaling_full/manifest.json --root tmp/full_suite_baseline --output outputs/full_optimization/baseline_search_1s.jsonl --timeout 1 --method search
python -m lazor.full_benchmark --manifest outputs/scaling_full/manifest.json --root tmp/full_suite_release --output outputs/full_optimization/release_search_1s.jsonl --timeout 1 --method search
```
